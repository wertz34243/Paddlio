# Paddlio real week test plan

Status: vorbereitet fuer Development-Wochenlauf.
Umgebung: develop / Development-Testdaten.
Ziel: reale Trainer- und Sportler-Workflows eine Woche lang pruefen, ohne Production-Daten zu verwenden.

## Montag

- Wochenplan pruefen.
- Training oeffnen.
- Kleine Aenderung speichern.
- Athlete prueft, ob die Aenderung sichtbar ist.

## Dienstag

- Vorlage verwenden.
- Training starten.
- Feedback speichern.
- Coach prueft, ob Feedback sichtbar ist.

## Mittwoch

- Training verschieben.
- Reload ausfuehren.
- Zweites Geraet pruefen.

## Donnerstag

- Journal pruefen.
- Soll/Ist pruefen.
- Tablet Portrait testen.

## Freitag

- Tablet Landscape fuer Planung nutzen.
- Drag & Drop testen.
- Quick Edit testen.
- Athlete-Zuweisung pruefen.

## Samstag

- Wettkampf- oder Sondertermin nur anzeigen.
- Kalenderuebersicht pruefen.

## Sonntag

- Wochenrueckblick durchfuehren.
- Gefundene Probleme priorisieren.

## Tagesprotokoll

Fuer jeden Testtag erfassen:

| Feld | Eintrag |
| --- | --- |
| Datum |  |
| Geraet |  |
| Rolle |  |
| Was wollte ich tun? |  |
| Wie viele Aktionen/Klicks? |  |
| Was war unklar? |  |
| Was war zu gross/klein? |  |
| Was war langsam? |  |
| Was hat gut funktioniert? |  |
| Fehler? |  |
| Screenshot vorhanden? |  |
| Prioritaet |  |

## Abnahmekriterien

- Coach kann Trainings erstellen, aendern und zuweisen.
- Athlete sieht zugewiesene Trainings.
- Feedback erscheint beim Coach.
- Reload erhaelt Daten korrekt.
- Keine Duplikate entstehen.
- Phone bleibt bedienbar.
- Tablet Portrait bleibt lesbar.
- Tablet Landscape bleibt Kalender-first.
